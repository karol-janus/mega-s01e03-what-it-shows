0002 · Match causes before merging reports

owner Karol Janus and Codex proposed reviewed 2026-10-31 · 0 days ago

Proposed replacement for: accepted decision 0001. That accepted record remains unchanged; this proposal needs the support desk’s acceptance.

Context

The #4471 investigation shows that subject matching hid a separate form-hint bug in a parser ticket. Intake tags also disagree with tenant-aware classification.

Decision proposed

Read the body, resolve the tenant, determine date order and form, then classify using causeOf. Merge only when sameCause is true. Subject matching can find candidate tickets, but cannot authorize a merge. Unknown tenants and unexplained symptoms stay unmerged for investigation. Count each report ID once and keep membership auditable.

Consequences

Triage requires more context than a subject comparison. Different subjects can share one cause; the same subject can require separate tickets. Fixing the parser and fixing the form hint are separate engineering tasks. Recheck uncertain reports against actual input and output.
